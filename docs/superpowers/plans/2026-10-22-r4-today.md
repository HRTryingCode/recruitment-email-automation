# R4 — Today page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the old Dashboard at `/today` with a small, glanceable "Today" page backed by one read-only `GET /api/today` summary (≤4 SQL queries), then flip the design-system guard + ESLint rules to error.

**Architecture:** `backend/src/services/today.service.ts` builds four `Prisma.Sql` statements (inbox aggregate reusing the inbox CTE, inbound messages, sent drafts per day, Lever counts) and shapes them into a `TodaySummary`. `routes/today.ts` mounts it under `requireAuth`. The frontend `TodayPage` composes four small components under `components/today/` from `fetchToday` + the already-cached `fetchMailboxes` / `fetchSyncHealth`.

**Tech Stack:** Express + Prisma raw SQL (Postgres, tested on PGlite), React 18 + TanStack Query, shadcn/ui (Card, Table, Badge, Button, Empty, Skeleton, Alert, chart = Recharts 3), Vitest + MSW, Playwright.

**Spec:** the R4 brief (orchestrator dispatch, 2026-10-22) — quoted in the PR.

## Global Constraints

- Every test/build command prefixed `nice -n 19`; vitest `--maxWorkers=2`; never loop full suites > 3×.
- No migration. No writes in `/api/today` (no `releaseExpiredSnoozes`; the CTE already treats `snoozedUntil <= now` as un-snoozed).
- `GET /api/today` is `requireAuth`, accepts optional `mailboxId` (cuid), runs **≤ 4** `$queryRaw` calls.
- Day buckets and "today" use America/New_York (`etMidnight`), matching the Inbox `sent_today` view.
- Don't edit R3 files (CandidateTable, LookupBar, LookupIntegrations, LeverBadge, AddToLever*, JobCombobox, Gem*).
- No PII beyond what authenticated endpoints already return; no email bodies.

## Review Focus

1. No mailboxes / brand-new install → every section shows an empty state, no NaN, chart shows zero-filled 14 days. (Task 4 test `renders empty states`.)
2. A day with no activity inside the 14-day window → series still has 14 consecutive ET days, zero-filled. (Task 1 test `zero-fills 14 ET days`.)
3. `mailboxId` filter set in the shell → summary is scoped to that mailbox (inbox CTE + messages + sent); Lever counts stay team-wide only if the candidate has no mailbox — scope them too. (Task 1 test `scopes to mailboxId`.)
4. `/api/today` fails while mailboxes load fine → error Alert with retry, rest of page not blank. (Task 4 test `shows an error state`.)
5. Expired snooze (`snoozedUntil <= now`) counts as waiting again without a write. (Task 1 test.)

**Interfaces:**
- Produces: `todayInboxSql(p: {now, mailboxId?}): Prisma.Sql` → rows `{view, mailboxId, count, oldestAt, expiringSoon}`; `todayMessagesSql(p)` → rows `{kind:'last'|'day', mailboxId, day, at, count}`; `todaySentSql(p)` → `{day, count}`; `todayLeverSql(p)` → one row `{interestedNotInLever, addedToday, addedThisWeek}`; `getTodaySummary(q:{mailboxId?}, now=new Date()): Promise<TodaySummary>`.
- `TodaySummary = { generatedAt; views:{needs_review,interested,not_interested}; sentToday; oldestWaitingAt: string|null; draftsExpiringSoon; mailboxes: Array<{mailboxId, waiting, sentToday, lastReceivedAt|null}>; lever:{interestedNotInLever, addedToday, addedThisWeek}; series: Array<{day:'YYYY-MM-DD', received, sent}> (14, oldest first) }`.
- "Expiring soon" = live PENDING/APPROVED draft that expires (createdAt + DRAFT_EXPIRY_DAYS) within 24h. "Received" = message on a candidate thread from an address that is not the mailbox's own/sendAs. "Sent" = EmailDraft SENT by sentAt. Week = since Monday 00:00 ET. Lever added = `SystemLog` `LEVER_OPPORTUNITY_CREATED`. Interested not in Lever = `status='INTERESTED' AND leverState='NOT_FOUND'`.
